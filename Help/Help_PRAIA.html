Descripción

PR-AI Assistant es un asistente de inteligencia artificial diseñado específicamente para el triaje forense digital. Forma parte de la suite PRImager Forensic Core.

Su característica principal es la ejecución 100% local de modelos de lenguaje (LLMs) y modelos de visión (VLMs), garantizando la privacidad absoluta de los datos, el cumplimiento estricto de la cadena de custodia y la no alteración de la evidencia digital. Ningún dato sale de la máquina del perito.

El motor de inferencia es llama.cpp, ejecutando modelos de la familia Google Gemma 4 (licencia Apache 2.0) con soporte para aceleración GPU NVIDIA (CUDA) y operación en CPU para equipos sin GPU dedicada.

Modos de Operación

La aplicación ofrece dos modos de uso con distintos niveles de seguridad y auditoría:

Modo Investigación

Diseñado para el análisis de evidencia digital en el marco de una causa judicial. Requiere:

  • Formulario de identificación obligatorio: Nombre y legajo del perito, número de causa judicial y juzgado interviniente.
  • Aceptación del descargo legal: Basado en buenas prácticas de la RFC 3227 (Guidelines for Evidence Collection and Archiving). El hash SHA-256 del descargo se registra en el log forense.
  • Panel de contexto forense: Permite cargar archivos de texto, CSV, JSON, volcados hexadecimales e imágenes para inyectarlos como contexto de análisis.
  • Logging forense completo: Cada interacción se registra con timestamp UTC y hash SHA-256 en un archivo de auditoría de solo adición (append-only).
  • Exportación de sesión: Al finalizar, se puede exportar un reporte estructurado de la sesión en formatos TXT, HTML o JSON, con hash SHA-256 del documento final.
Importante: El modelo de IA asiste al perito pero nunca lo reemplaza. Toda respuesta generada por IA debe ser verificada por el perito antes de incorporarse a cualquier informe o actuación judicial. Las respuestas incluyen automáticamente un descargo al pie indicando su origen artificial.

Modo Consulta (Academia PR)

Funciona como un entorno académico aislado (sandbox) para consultas sobre:

  • Legislación y normativa (Ley 26.388, Convenio de Budapest, RFC 3227, ISO 27037).
  • Conceptos y procedimientos de informática forense.
  • Estructuras de datos, formatos de archivo y artefactos digitales.
Nota: En modo consulta el modelo tiene instrucciones explícitas de rechazar el análisis de evidencia real. No se habilita el panel de carga de archivos ni la exportación de sesión forense.

Guía de Uso

  1. Seleccionar modo de operación: Al iniciar la aplicación, elija entre Modo Investigación o Academia PR según el contexto de trabajo.
  2. Seleccionar perfil de modelo: En el panel izquierdo, elija el perfil de IA adecuado al hardware disponible:
    PerfilDescripciónHardware
    RendimientoSolo texto, rápidoCPU suficiente
    EquilibradoTexto + imágenesGPU recomendada
    Máxima CalidadMáxima precisiónGPU potente requerida
  3. Iniciar el servidor: Presione el botón "Iniciar". El sistema cargará el modelo en memoria (10-30 segundos la primera vez). El indicador cambiará a verde "Listo" cuando esté operativo. En la esquina inferior izquierda se muestra la GPU detectada.
  4. Ajustar parámetros (opcional):
    • Thinking Mode: Habilita el modo de razonamiento extendido del modelo. Produce respuestas más reflexivas pero más lentas.
    • Temperatura: Controla la creatividad de las respuestas (0.0 = determinista, 2.0 = muy creativo). Valor recomendado para forense: 0.3-0.7.
    • Máx. respuesta: Límite de tokens para la respuesta generada.
  5. Cargar contexto forense (solo Modo Investigación):
    • Botón 📎 — Cargar archivos de texto, CSV, JSON o volcados hexadecimales.
    • Botón 🖼️ — Cargar imágenes para análisis visual (requiere perfil con soporte de Visión).
    • También puede arrastrar archivos directamente sobre el área de chat.

    Los archivos cargados aparecen en el panel derecho "Contexto Forense" con su tipo y tamaño. El contador de tokens estimados se actualiza en tiempo real.

  6. Interactuar con el asistente: Escriba su consulta en el campo de texto inferior y presione Enter o el botón de envío. Use Shift+Enter para saltos de línea sin enviar. La respuesta se muestra en tiempo real (streaming).
  7. Exportar sesión (solo Modo Investigación): Presione "Exportar Sesión" en el panel izquierdo. Seleccione el formato (TXT, HTML o JSON) y la ubicación. El archivo exportado incluye un hash SHA-256 de integridad.
Consejo: Si el modelo no puede generar respuesta (contexto excedido), utilice el botón "Nueva Sesión" para reiniciar la conversación. Para sesiones largas, puede aumentar el tamaño de contexto editando ctx_size en Config/settings.json.

Gestión de Ventana de Contexto

Los modelos de IA locales operan con ventanas de contexto limitadas. PR-AI Assistant implementa mecanismos automáticos de protección:

  • Validación de archivos: Los archivos cargados se validan rigurosamente. Se rechazan binarios ejecutables (.exe, .dll) y se aplican límites de caracteres (50.000 para texto, 5.000 para hexadecimal). El contenido excedente se trunca automáticamente.
  • Recorte automático del historial: Antes de cada consulta, el sistema calcula los tokens estimados. Si el sistema de prompts, el contexto forense y el historial superan el límite configurado, se recortan los mensajes más antiguos preservando siempre las instrucciones base.
  • Indicadores visuales: El panel derecho muestra en tiempo real los tokens estimados, el espacio disponible y una advertencia cuando el contexto está cerca del límite.

Búsqueda Web (SearXNG)

La edición comercial puede enriquecer una consulta con resultados web actuales. Es la única función del programa que usa la red, y está construida sobre tres decisiones deliberadas:

  • La decide el usuario, nunca el modelo. La búsqueda se activa con el botón 🌐 junto al campo de texto, consulta por consulta. No hay tool-calling: el modelo no puede decidir salir a Internet por su cuenta.
  • No existe en la edición institucional. No es un permiso desactivado por configuración: el código de red directamente no se compila en ese binario. El botón 🌐 ni siquiera aparece.
  • El Modo Investigación la bloquea siempre. Aunque el perfil activo la habilite, al entrar en Modo Investigación queda forzada a apagado.
Advertencia forense: con la búsqueda activada, el texto de la consulta sale de la máquina hacia el servidor de búsqueda y se descargan páginas de sitios de terceros. La evidencia cargada no se transmite, pero la pregunta sí. Por eso está prohibida en Modo Investigación. Cada búsqueda queda registrada en el log de auditoría con el proveedor y la cantidad de fuentes leídas.

Por qué SearXNG

SearXNG es un metabuscador libre que consulta a varios motores y devuelve los resultados agregados. Se eligió porque no requiere cuenta, ni clave de API, ni tarjeta de crédito, y porque la consulta sale de un servidor que controla el propio usuario. En una herramienta pericial eso es más defendible que una clave corporativa contra un servicio comercial: no queda un tercero con un registro de búsquedas asociado a una identidad de facturación.

Levantar una instancia propia

Es la forma recomendada. Requiere Docker Desktop (gratuito). Una sola vez:

docker run -d --name searxng -p 8080:8080 ^
  -v "D:\PROYECTOS\PR-Tools\searxng:/etc/searxng" ^
  --restart unless-stopped searxng/searxng

El contenedor genera un archivo settings.yml en la carpeta indicada. Hay que habilitar el formato JSON, que viene desactivado de fábrica:

search:
  formats:
    - html
    - json

Después, docker restart searxng. Con --restart unless-stopped el contenedor vuelve a levantarse solo al reiniciar el equipo.

Error más frecuente: si se omite el paso del JSON, la instancia funciona perfecto en el navegador pero rechaza las consultas de la aplicación con un error 403. El mensaje que muestra el programa indica el archivo y la clave exacta que hay que tocar.

Configurar la aplicación

  1. Abrir el panel lateral con ☰ y bajar hasta BÚSQUEDA WEB.
  2. En Instancia de SearXNG, escribir la dirección: http://127.0.0.1:8080. Se acepta también sin el esquema (127.0.0.1:8080).
  3. Verificar que el estado debajo del campo diga «Instancia configurada» en verde.
  4. Elegir la frescura de los resultados: último día, última semana, último mes o sin filtro.
Nota: la dirección se muestra en claro, no enmascarada. No es una credencial, y conviene que el perito pueda verificar a simple vista contra qué servidor sale la consulta.

Qué ocurre al buscar

Con el botón 🌐 encendido, la aplicación busca, descarga las 3 primeras páginas (10 segundos de espera máxima cada una), las convierte a texto plano y arma la consulta al modelo con las fuentes numeradas y la instrucción de citar con [n]. En pantalla se ve Buscando… y luego Leyendo 3 páginas….

Bajo la respuesta aparece un panel desplegable de fuentes con el título, la URL en la que se puede hacer clic, la fecha y si la página pudo leerse o no. Verificar las fuentes es responsabilidad del perito.

Los fallos no interrumpen la consulta: si una página no responde, se informa y se sigue con las demás. Si no se puede leer ninguna, el modelo responde igual, sin fuentes y avisando en pantalla.

Sobre el historial: el modelo recibe la consulta enriquecida con el texto de las páginas, pero en el historial de la conversación se guarda la pregunta original. De lo contrario cada turno arrastraría miles de tokens de páginas web y el contexto se agotaría en dos intercambios.

Instancias públicas

Se puede apuntar a una instancia pública de SearXNG en lugar de una propia, pero con reservas: la mayoría tiene el formato JSON deshabilitado, suelen limitar el uso automatizado (error 429) y significa confiar la consulta a un servidor de un tercero desconocido. Para trabajo pericial, siempre una instancia propia.

Auditoría y Trazabilidad

Cada sesión genera un archivo de log forense (ai-session-YYYY-MM-DD.log) en la carpeta Logs/ con las siguientes características:

  • Formato de solo adición (append-only): no se pueden modificar entradas previas.
  • Cada entrada incluye timestamp UTC y hash SHA-256 del contenido.
  • Se registran: inicio de sesión, validación de descargo, consultas del perito, respuestas del modelo, carga de contexto, errores y exportaciones.

Esto garantiza la inalterabilidad del registro ante escrutinio judicial.

Description

PR-AI Assistant is an artificial intelligence assistant specifically designed for digital forensic triage. It is part of the PRImager Forensic Core suite.

Its main feature is the 100% local execution of language models (LLMs) and vision models (VLMs), ensuring absolute data privacy, strict chain of custody compliance, and no alteration of digital evidence. No data ever leaves the examiner's machine.

The inference engine is llama.cpp, running models from the Google Gemma 4 family (Apache 2.0 license) with NVIDIA GPU acceleration (CUDA) support and CPU fallback for machines without a dedicated GPU.

Operating Modes

The application offers two operating modes with different security and auditing levels:

Investigation Mode

Designed for digital evidence analysis within the framework of a judicial case. Requires:

  • Mandatory identification form: Examiner name and badge number, case number, and court of jurisdiction.
  • Legal disclaimer acceptance: Based on RFC 3227 best practices (Guidelines for Evidence Collection and Archiving). The SHA-256 hash of the disclaimer is recorded in the forensic log.
  • Forensic context panel: Allows loading text files, CSV, JSON, hex dumps, and images to inject them as analysis context.
  • Full forensic logging: Every interaction is logged with UTC timestamp and SHA-256 hash in an append-only audit file.
  • Session export: Upon completion, a structured session report can be exported in TXT, HTML, or JSON format, with SHA-256 hash of the final document.
Important: The AI model assists the examiner but never replaces them. Every AI-generated response must be verified by the examiner before being incorporated into any report or judicial proceeding. Responses automatically include a disclaimer indicating their artificial origin.

Consultation Mode (Academia PR)

Functions as an isolated academic sandbox for queries about:

  • Legislation and regulations (Law 26.388, Budapest Convention, RFC 3227, ISO 27037).
  • Digital forensics concepts and procedures.
  • Data structures, file formats, and digital artifacts.
Note: In consultation mode, the model has explicit instructions to reject analysis of real evidence. The file loading panel and forensic session export are disabled.

Usage Guide

  1. Select operating mode: Upon launching the application, choose between Investigation Mode or Academia PR according to your work context.
  2. Select model profile: In the left panel, choose the AI profile appropriate for the available hardware:
    ProfileDescriptionHardware
    PerformanceText only, fastCPU sufficient
    BalancedText + imagesGPU recommended
    Maximum QualityMaximum precisionPowerful GPU required
  3. Start the server: Press the "Start" button. The system will load the model into memory (10-30 seconds on first run). The indicator will turn green "Ready" when operational. The detected GPU is shown in the bottom-left corner.
  4. Adjust parameters (optional):
    • Thinking Mode: Enables the model's extended reasoning mode. Produces more thoughtful but slower responses.
    • Temperature: Controls response creativity (0.0 = deterministic, 2.0 = very creative). Recommended for forensics: 0.3-0.7.
    • Max. response: Token limit for the generated response.
  5. Load forensic context (Investigation Mode only):
    • Button 📎 — Load text files, CSV, JSON, or hex dumps.
    • Button 🖼️ — Load images for visual analysis (requires profile with Vision support).
    • You can also drag and drop files directly onto the chat area.

    Loaded files appear in the right panel "Forensic Context" with their type and size. The estimated token counter updates in real time.

  6. Interact with the assistant: Type your query in the bottom text field and press Enter or the send button. Use Shift+Enter for line breaks without sending. The response is displayed in real time (streaming).
  7. Export session (Investigation Mode only): Press "Export Session" in the left panel. Select the format (TXT, HTML, or JSON) and location. The exported file includes a SHA-256 integrity hash.
Tip: If the model cannot generate a response (context exceeded), use the "New Session" button to restart the conversation. For long sessions, you can increase the context size by editing ctx_size in Config/settings.json.

Context Window Management

Local AI models operate with limited context windows. PR-AI Assistant implements automatic protection mechanisms:

  • File validation: Loaded files are rigorously validated. Executable binaries (.exe, .dll) are rejected, and character limits are applied (50,000 for text, 5,000 for hexadecimal). Excess content is automatically truncated.
  • Automatic history trimming: Before each query, the system estimates token usage. If the system prompt, forensic context, and chat history exceed the configured limit, the oldest messages are trimmed while always preserving base instructions.
  • Visual indicators: The right panel displays estimated tokens, available space, and a warning when context is near the limit in real time.

Web Search (SearXNG)

The commercial edition can enrich a query with current web results. It is the only feature in the program that uses the network, and it rests on three deliberate decisions:

  • The user decides, never the model. Search is enabled with the 🌐 button next to the text field, one query at a time. There is no tool-calling: the model cannot decide to reach the Internet on its own.
  • It does not exist in the institutional edition. This is not a permission turned off in a config file: the networking code is simply not compiled into that binary. The 🌐 button does not even appear.
  • Investigation Mode always blocks it. Even if the active profile allows it, entering Investigation Mode forces it off.
Forensic warning: with search enabled, the query text leaves the machine towards the search server, and pages from third-party sites are downloaded. Loaded evidence is never transmitted, but the question is. That is why it is forbidden in Investigation Mode. Every search is recorded in the audit log with the provider and the number of sources read.

Why SearXNG

SearXNG is a free metasearch engine that queries several engines and returns aggregated results. It was chosen because it requires no account, no API key and no credit card, and because the query leaves from a server the user controls. In a forensic tool that is more defensible than a corporate key against a commercial service: no third party is left holding a search log tied to a billing identity.

Running your own instance

This is the recommended approach. It requires Docker Desktop (free). Once only:

docker run -d --name searxng -p 8080:8080 ^
  -v "D:\PROYECTOS\PR-Tools\searxng:/etc/searxng" ^
  --restart unless-stopped searxng/searxng

The container generates a settings.yml file in that folder. You must enable the JSON format, which is disabled by default:

search:
  formats:
    - html
    - json

Then run docker restart searxng. With --restart unless-stopped the container comes back up on its own after a reboot.

Most common error: if the JSON step is skipped, the instance works perfectly in a browser but rejects the application's queries with a 403 error. The message shown by the program names the exact file and key to change.

Configuring the application

  1. Open the side panel with ☰ and scroll down to WEB SEARCH.
  2. Under SearXNG instance, enter the address: http://127.0.0.1:8080. It is also accepted without the scheme (127.0.0.1:8080).
  3. Check that the status below the field reads "Instance configured" in green.
  4. Choose the result freshness: last day, last week, last month, or no filter.
Note: the address is shown in plain text, not masked. It is not a credential, and the examiner should be able to see at a glance which server the query is going to.

What happens during a search

With the 🌐 button on, the application searches, downloads the first 3 pages (10-second timeout each), converts them to plain text and builds the model query with numbered sources and an instruction to cite using [n]. The screen shows Searching… and then Reading 3 pages….

Below the answer, a collapsible sources panel lists the title, a clickable URL, the date, and whether each page could be read. Verifying the sources is the examiner's responsibility.

Failures do not abort the query: if a page does not respond, it is reported and the rest continue. If none can be read, the model answers anyway, without sources and with an on-screen notice.

About history: the model receives the query enriched with the page text, but the conversation history stores the original question. Otherwise every turn would drag thousands of tokens of web pages along and the context would be exhausted in two exchanges.

Public instances

You can point to a public SearXNG instance instead of your own, with caveats: most have the JSON format disabled, they usually rate-limit automated use (429 error), and it means trusting your query to an unknown third party's server. For forensic work, always use your own instance.

Auditing and Traceability

Each session generates a forensic log file (ai-session-YYYY-MM-DD.log) in the Logs/ folder with the following characteristics:

  • Append-only format: previous entries cannot be modified.
  • Each entry includes UTC timestamp and SHA-256 hash of the content.
  • Recorded events include: session start, disclaimer validation, examiner queries, model responses, context loading, errors, and exports.

This ensures record immutability under judicial scrutiny.
