PATAGONIA ROBOT
PR-AI Assistant
v1.0.0 — Asistente de IA Local para Triaje Forense Digital

Descripción

PR-AI Assistant es un asistente de inteligencia artificial diseñado específicamente para el triaje forense digital. Forma parte de la suite PRImager Forensic Core.

Su característica principal es la ejecución 100% local de modelos de lenguaje (LLMs) y modelos de visión (VLMs), garantizando la privacidad absoluta de los datos, el cumplimiento estricto de la cadena de custodia y la no alteración de la evidencia digital. Ningún dato sale de la máquina del perito.

El motor de inferencia es llama.cpp, con los modelos GGUF que elige y descarga cada usuario: la aplicación se publica sin modelos y recomienda la cuantización que conviene a cada PC. Acelera con la placa de video —CUDA en NVIDIA, Vulkan en AMD e Intel— y también corre en CPU en equipos sin placa dedicada.

Modos de Operación

La aplicación ofrece dos modos de uso con distintos niveles de seguridad y auditoría:

Modo Investigación

Diseñado para el análisis de evidencia digital en el marco de una causa judicial. Requiere:

  • Formulario de identificación obligatorio: Nombre y legajo del perito, número de causa judicial y juzgado interviniente.
  • Aceptación del descargo legal: Basado en buenas prácticas de la RFC 3227 (Guidelines for Evidence Collection and Archiving). El hash SHA-256 del descargo se registra en el log forense.
  • Panel de contexto forense: Permite cargar archivos de texto, CSV, JSON, volcados hexadecimales e imágenes para inyectarlos como contexto de análisis.
  • Logging forense completo: Cada interacción se registra con timestamp UTC y hash SHA-256 en un archivo de auditoría de solo adición (append-only).
  • Exportación de sesión: Al finalizar, se puede exportar un reporte estructurado de la sesión en formatos TXT, HTML o JSON, con hash SHA-256 del documento final.
Importante: El modelo de IA asiste al perito pero nunca lo reemplaza. Toda respuesta generada por IA debe ser verificada por el perito antes de incorporarse a cualquier informe o actuación judicial. Las respuestas incluyen automáticamente un descargo al pie indicando su origen artificial.

Modo Consulta (Academia PR)

Funciona como un entorno académico aislado (sandbox) para consultas sobre:

  • Legislación y normativa (Ley 26.388, Convenio de Budapest, RFC 3227, ISO 27037).
  • Conceptos y procedimientos de informática forense.
  • Estructuras de datos, formatos de archivo y artefactos digitales.
Nota: En modo consulta el modelo tiene instrucciones explícitas de rechazar el análisis de evidencia real. No se habilita el panel de carga de archivos ni la exportación de sesión forense.

Guía de Uso

  1. Seleccionar modo de operación: Al iniciar la aplicación, elija entre Modo Investigación o Academia PR según el contexto de trabajo. Al pie de esa pantalla está el selector de idioma: «Automático» sigue al idioma de Windows; el cambio se aplica al volver a abrir la aplicación.
  2. Seleccionar perfil de ejecución: En el panel izquierdo. Automático, el que viene elegido, lee el modelo y la PC —placa de cualquier marca, RAM y procesador— y fija solo el contexto, las capas que van a la placa y los hilos; debajo de los botones dice qué eligió. Los otros tres son valores fijos para quien prefiera elegir a mano:
    PerfilDescripciónHardware
    AutomáticoCalculado para el modelo y la PCCualquiera
    RendimientoSolo texto, rápidoCPU suficiente
    EquilibradoTexto + imágenesGPU recomendada
    Máxima CalidadMáxima precisiónGPU potente requerida
  3. Iniciar el servidor: Presione el botón "Iniciar". El sistema cargará el modelo en memoria (10-30 segundos la primera vez). El indicador cambiará a verde "Listo" cuando esté operativo. En la esquina inferior izquierda se muestra la GPU detectada.
  4. Ajustar parámetros (opcional):
    • Thinking Mode: Habilita el modo de razonamiento extendido del modelo. Produce respuestas más reflexivas pero más lentas.
    • Temperatura: Controla la creatividad de las respuestas (0.0 = determinista, 2.0 = muy creativo). Valor recomendado para forense: 0.3-0.7.
    • Máx. respuesta: Límite de tokens para la respuesta generada.
  5. Cargar archivos:
    • Botón del clip — Cargar archivos de texto, CSV, JSON o volcados hexadecimales.
    • Botón de la imagen — Cargar imágenes para análisis visual (requiere perfil con soporte de Visión).
    • También puede arrastrar archivos directamente sobre el área de chat.

    Qué ocurre con lo que se carga depende del modo, y la diferencia es importante:

    • En Modo Investigación es evidencia. Los archivos aparecen en el panel derecho "Contexto Forense" con su tipo y tamaño, se inyectan en el contexto de análisis, permanecen disponibles durante toda la sesión y quedan registrados en el log de auditoría. El contador de tokens estimados se actualiza en tiempo real.
    • En Modo General es un adjunto del mensaje. Los archivos aparecen como etiquetas sobre el cuadro de texto, se envían junto con esa única consulta y luego se descartan. No son evidencia, no entran al panel de contexto forense y no permanecen en la sesión. Del log solo queda constancia de qué archivo se adjuntó —nombre, tamaño y tipo—, nunca su contenido.

    Los botones de carga se muestran según el perfil de uso activo. El Modo Investigación siempre los habilita: cargar evidencia es parte del marco institucional y un perfil no puede quitarlo.

  6. Interactuar con el asistente: Escriba su consulta en el campo de texto inferior y presione Enter o el botón de envío. Use Shift+Enter para saltos de línea sin enviar. La respuesta se muestra en tiempo real (streaming).
  7. Exportar sesión (solo Modo Investigación): Presione "Exportar Sesión" en el panel izquierdo. Seleccione el formato (TXT, HTML o JSON) y la ubicación. El archivo exportado incluye un hash SHA-256 de integridad.
Consejo: Si el modelo no puede generar respuesta (contexto excedido), utilice el botón "Nueva Sesión" para reiniciar la conversación. Para sesiones largas, puede aumentar el tamaño de contexto editando ctx_size en Config/settings.json.

Gestión de Ventana de Contexto

Los modelos de IA locales operan con ventanas de contexto limitadas. PR-AI Assistant implementa mecanismos automáticos de protección:

  • Validación de archivos: Los archivos cargados se validan rigurosamente. Se rechazan binarios ejecutables (.exe, .dll) y se aplican límites de caracteres (50.000 para texto, 5.000 para hexadecimal). El contenido excedente se trunca automáticamente.
  • Recorte automático del historial: Antes de cada consulta, el sistema calcula los tokens estimados. Si el sistema de prompts, el contexto forense y el historial superan el límite configurado, se recortan los mensajes más antiguos preservando siempre las instrucciones base.
  • Indicadores visuales: El panel derecho muestra en tiempo real los tokens estimados, el espacio disponible y una advertencia cuando el contexto está cerca del límite.

Búsqueda Web (SearXNG)

La edición comercial puede enriquecer una consulta con resultados web actuales. Es la única función del programa que usa la red, y está construida sobre tres decisiones deliberadas:

  • La decide el usuario, nunca el modelo. La búsqueda se activa con el botón del globo junto al campo de texto, consulta por consulta. El botón aparece recién cuando se carga la dirección del buscador en el panel lateral, sección BÚSQUEDA WEB. No hay tool-calling: el modelo no puede decidir salir a Internet por su cuenta.
  • No existe en la edición institucional. No es un permiso desactivado por configuración: el código de red directamente no se compila en ese binario. El botón del globo ni siquiera aparece.
  • El Modo Investigación la bloquea siempre. Aunque el perfil activo la habilite, al entrar en Modo Investigación queda forzada a apagado.
Advertencia forense: con la búsqueda activada, el texto de la consulta sale de la máquina hacia el servidor de búsqueda y se descargan páginas de sitios de terceros. La evidencia cargada no se transmite, pero la pregunta sí. Por eso está prohibida en Modo Investigación. Cada búsqueda queda registrada en el log de auditoría con el proveedor y la cantidad de fuentes leídas.

Por qué SearXNG

SearXNG es un metabuscador libre que consulta a varios motores y devuelve los resultados agregados. Se eligió porque no requiere cuenta, ni clave de API, ni tarjeta de crédito, y porque la consulta sale de un servidor que controla el propio usuario. En una herramienta pericial eso es más defendible que una clave corporativa contra un servicio comercial: no queda un tercero con un registro de búsquedas asociado a una identidad de facturación.

Levantar una instancia propia

Es la forma recomendada. Requiere Docker Desktop (gratuito). Una sola vez:

docker run -d --name searxng -p 8080:8080 ^
  -v "C:\searxng:/etc/searxng" ^
  --restart unless-stopped searxng/searxng

El contenedor genera un archivo settings.yml en la carpeta indicada. Hay que habilitar el formato JSON, que viene desactivado de fábrica:

search:
  formats:
    - html
    - json

Después, docker restart searxng. Con --restart unless-stopped el contenedor vuelve a levantarse solo al reiniciar el equipo.

Error más frecuente: si se omite el paso del JSON, la instancia funciona perfecto en el navegador pero rechaza las consultas de la aplicación con un error 403. El mensaje que muestra el programa indica el archivo y la clave exacta que hay que tocar.

Configurar la aplicación

  1. Abrir el menú lateral con el botón de arriba a la izquierda y bajar hasta BÚSQUEDA WEB.
  2. En Instancia de SearXNG, escribir la dirección: http://127.0.0.1:8080. Se acepta también sin el esquema (127.0.0.1:8080).
  3. Verificar que el estado debajo del campo diga «Instancia configurada» en verde.
  4. Elegir la frescura de los resultados: último día, última semana, último mes o sin filtro.
Nota: la dirección se muestra en claro, no enmascarada. No es una credencial, y conviene que el perito pueda verificar a simple vista contra qué servidor sale la consulta.

Qué ocurre al buscar

Con el botón del globo encendido, la aplicación pide 12 candidatos al buscador y los descarga en tandas paralelas hasta reunir 6 páginas leídas (10 segundos de espera máxima cada una, con un tope de 10 intentos), las convierte a texto plano y arma la consulta al modelo con las fuentes numeradas y la instrucción de citar con [n]. En pantalla se ve Buscando… y luego Leyendo páginas….

Se piden más candidatos que páginas a propósito: contra sitios reales, alrededor de una de cada cuatro descargas se rechaza —portales judiciales, redes sociales y algunos medios bloquean la lectura automática—, así que pedir 6 daría 4 o 5 en la práctica.

Bajo la respuesta aparece un panel desplegable de fuentes con el título, la URL en la que se puede hacer clic, la fecha y si la página pudo leerse o no. Verificar las fuentes es responsabilidad del perito.

Los fallos no interrumpen la consulta: si una página no responde, se informa y se sigue con las demás. Si no se puede leer ninguna, el modelo responde igual, sin fuentes y avisando en pantalla.

Sobre el historial: el modelo recibe la consulta enriquecida con el texto de las páginas, pero en el historial de la conversación se guarda la pregunta original. De lo contrario cada turno arrastraría miles de tokens de páginas web y el contexto se agotaría en dos intercambios.

Instancias públicas

Se puede apuntar a una instancia pública de SearXNG en lugar de una propia, pero con reservas: la mayoría tiene el formato JSON deshabilitado, suelen limitar el uso automatizado (error 429) y significa confiar la consulta a un servidor de un tercero desconocido. Para trabajo pericial, siempre una instancia propia.

Generación de Imágenes

La edición comercial puede generar imágenes a partir de un prompt, con un motor local que corre en la misma máquina. No hay servicio en la nube ni cuenta de por medio: los modelos están en el disco y la GPU hace el trabajo.

No existe en la edición institucional. Igual que la búsqueda web, no es un permiso desactivado: el código directamente no se compila en ese binario. Y en la edición comercial, el Modo Investigación la bloquea siempre, aunque el perfil activo la habilite. Una herramienta pericial que puede fabricar imágenes es un problema de credibilidad, no de funcionalidad.

Qué hace falta

Dos cosas, ninguna incluida en la distribución por su tamaño:

  • El motor: sd-server.exe, de stable-diffusion.cpp, en su versión CUDA para placas NVIDIA o en la Vulkan para AMD e Intel. La CUDA se descomprime en Tools\sd\bin\ y la Vulkan en Tools\sd\bin-vulkan\, junto a la aplicación; si están las dos, la aplicación elige la que corresponde a la placa. También se puede elegir a mano desde la ventana de modelos de imagen.
  • Un paquete de modelo: y acá está la diferencia con el chat. Un modelo de imagen son tres archivos, no uno: el modelo de difusión, el text encoder y el VAE. Si falta cualquiera de los tres, el motor no arranca.

En Modelos de imagen hay tres variantes de Z-Image Turbo para bajar con un botón: Q4_K (6,2 GB en total), Q6_K y Q8_0. La ventana marca como Recomendado la que conviene a tu placa —Q4_K hasta 16 GB de VRAM, Q6_K con 20 GB o más— y solo ofrece bajar lo que todavía no está: las tres comparten text encoder y VAE, así que la segunda variante baja un solo archivo. También se puede armar un paquete a mano apuntando a los tres archivos.

Cómo se usa

  1. Abrir el menú lateral con el botón de arriba a la izquierda y bajar hasta IMÁGENES.
  2. La primera vez, entrar en Modelos de imagen y descargar el recomendado, o apuntar a los tres archivos si ya se tienen.
  3. Si tenés más de uno bajado, elegir cuál usar en el desplegable de IMÁGENES, como se elige el modelo de lenguaje.
  4. Presionar Generar imágenes. Se abre una ventana aparte.
  5. Escribir el prompt, elegir el tamaño y presionar Generar imagen.

Apagar el motor de imágenes: debajo de los botones se ve si el motor de imágenes está encendido. Apagar lo baja sin tocar el chat, para devolverle la placa al modelo de lenguaje; se vuelve a encender solo con la próxima imagen. Detener, más arriba, apaga los dos.

Si no la vas a usar: en la pantalla de inicio, debajo del modelo, está el interruptor Generación de imágenes. Apagado, el motor de imágenes no se enciende nunca y la sección IMÁGENES del chat queda desactivada. Se recuerda para la próxima vez.

La ventana no es modal: se puede seguir conversando con el modelo de lenguaje mientras la imagen se genera. Los dos motores conviven en la misma placa porque el de imágenes carga los pesos solo mientras trabaja y los libera al terminar.

Se genera de a una por vez

Como en Gemini o ChatGPT: se pide una imagen y se espera. El botón de generar queda deshabilitado mientras hay una en curso, y el de cancelar corta esa generación y nada más. No hay cola ni lista de pendientes.

Cancelar detiene el motor y lo vuelve a levantar, que es lo único que corta de verdad una generación en curso. Tarda alrededor de un segundo y no deja archivos a medias.

El tamaño es una decisión de tiempo, no de memoria

Es lo contrario de lo que uno supone. Con el VAE dividido en tiles —que la aplicación activa siempre—, generar a 1024×1024 usa apenas unos 200 MB más de memoria de video que a 512×512, pero tarda unas tres veces más. El semáforo de la ventana informa si la configuración actual entra en la memoria libre y, si no entra, dice qué ajustar.

Cada imagen se puede reproducir

Junto a cada PNG se escribe un archivo .json del mismo nombre con todo lo necesario para volver a obtenerla: prompt, prompt negativo, tamaño, pasos, CFG, semilla, sampler, los tres archivos del modelo y la línea de comandos exacta con la que corrió el motor.

Sobre la semilla: aunque se elija «semilla aleatoria», el número lo sortea la aplicación y queda guardado. El motor acepta que se le pida una semilla al azar, pero después no informa cuál usó, y una imagen cuya semilla no se conoce no se puede volver a generar.

Las imágenes van a %APPDATA%\PatagoniaRobot\PR-AIA\ImagenesGeneradas. El botón Abrir carpeta lleva ahí directamente.

Qué queda en el registro

Si el perfil activo exige auditoría, se registra el hecho de haber generado una imagen —archivo, tamaño, pasos, CFG, semilla y modelo— pero nunca el prompt. Vale el mismo criterio que para los archivos adjuntos en modo personal: auditar lo que el usuario escribe lo convertiría en otra cosa. El prompt está en el .json al lado de la imagen, que es donde sirve.

Auditoría y Trazabilidad

Cada sesión genera un archivo de log forense (ai-session-YYYY-MM-DD.log) en la carpeta Logs/ con las siguientes características:

  • Formato de solo adición (append-only): no se pueden modificar entradas previas.
  • Cada entrada incluye timestamp UTC y hash SHA-256 del contenido.
  • Se registran: inicio de sesión, validación de descargo, consultas del perito, respuestas del modelo, carga de contexto, errores y exportaciones.

Esto garantiza la inalterabilidad del registro ante escrutinio judicial.

  • PR-AI Assistant nunca accede directamente a la evidencia original. Solo trabaja con datos ya extraídos y proporcionados por el perito.

Description

PR-AI Assistant is an artificial intelligence assistant specifically designed for digital forensic triage. It is part of the PRImager Forensic Core suite.

Its main feature is the 100% local execution of language models (LLMs) and vision models (VLMs), ensuring absolute data privacy, strict chain of custody compliance, and no alteration of digital evidence. No data ever leaves the examiner's machine.

The inference engine is llama.cpp, with the GGUF models each user chooses and downloads: the application ships without models and recommends the quantization that suits each PC. It accelerates with the graphics card —CUDA on NVIDIA, Vulkan on AMD and Intel— and also runs on the CPU on machines without a dedicated card.

Operating Modes

The application offers two operating modes with different security and auditing levels:

Investigation Mode

Designed for digital evidence analysis within the framework of a judicial case. Requires:

  • Mandatory identification form: Examiner name and badge number, case number, and court of jurisdiction.
  • Legal disclaimer acceptance: Based on RFC 3227 best practices (Guidelines for Evidence Collection and Archiving). The SHA-256 hash of the disclaimer is recorded in the forensic log.
  • Forensic context panel: Allows loading text files, CSV, JSON, hex dumps, and images to inject them as analysis context.
  • Full forensic logging: Every interaction is logged with UTC timestamp and SHA-256 hash in an append-only audit file.
  • Session export: Upon completion, a structured session report can be exported in TXT, HTML, or JSON format, with SHA-256 hash of the final document.
Important: The AI model assists the examiner but never replaces them. Every AI-generated response must be verified by the examiner before being incorporated into any report or judicial proceeding. Responses automatically include a disclaimer indicating their artificial origin.

Consultation Mode (PR Academy)

Functions as an isolated academic sandbox for queries about:

  • Legislation and regulations (Law 26.388, Budapest Convention, RFC 3227, ISO 27037).
  • Digital forensics concepts and procedures.
  • Data structures, file formats, and digital artifacts.
Note: In consultation mode, the model has explicit instructions to reject analysis of real evidence. The file loading panel and forensic session export are disabled.

Usage Guide

  1. Select operating mode: Upon launching the application, choose between Investigation Mode or PR Academy according to your work context. At the bottom of that screen is the language selector: «Automatic» follows the Windows language; a change applies when the application is opened again.
  2. Select execution profile: In the left panel. Automatic, selected by default, reads the model and the PC —any brand of GPU, RAM and CPU— and sets the context size, the layers sent to the GPU and the threads by itself; below the buttons it shows what it chose. The other three are fixed values for those who prefer to choose by hand:
    ProfileDescriptionHardware
    AutomaticComputed for the model and the PCAny
    PerformanceText only, fastCPU sufficient
    BalancedText + imagesGPU recommended
    Maximum QualityMaximum precisionPowerful GPU required
  3. Start the server: Press the "Start" button. The system will load the model into memory (10-30 seconds on first run). The indicator will turn green "Ready" when operational. The detected GPU is shown in the bottom-left corner.
  4. Adjust parameters (optional):
    • Thinking Mode: Enables the model's extended reasoning mode. Produces more thoughtful but slower responses.
    • Temperature: Controls response creativity (0.0 = deterministic, 2.0 = very creative). Recommended for forensics: 0.3-0.7.
    • Max. response: Token limit for the generated response.
  5. Load files:
    • Paperclip button — Load text files, CSV, JSON, or hex dumps.
    • Image button — Load images for visual analysis (requires a profile with Vision support).
    • You can also drag and drop files directly onto the chat area.

    What happens to what you load depends on the mode, and the difference matters:

    • In Investigation Mode it is evidence. Files appear in the right panel "Forensic Context" with their type and size, are injected into the analysis context, stay available for the whole session and are recorded in the audit log. The estimated token counter updates in real time.
    • In General Mode it is a message attachment. Files appear as tags above the text box, are sent with that single query and are then discarded. They are not evidence, do not enter the forensic context panel and do not stay in the session. The log only records which file was attached —name, size and type—, never its content.

    The load buttons are shown according to the active usage profile. Investigation Mode always enables them: loading evidence is part of the institutional framework and a profile cannot remove it.

  6. Interact with the assistant: Type your query in the bottom text field and press Enter or the send button. Use Shift+Enter for line breaks without sending. The response is displayed in real time (streaming).
  7. Export session (Investigation Mode only): Press "Export Session" in the left panel. Select the format (TXT, HTML, or JSON) and location. The exported file includes a SHA-256 integrity hash.
Tip: If the model cannot generate a response (context exceeded), use the "New Session" button to restart the conversation. For long sessions, you can increase the context size by editing ctx_size in Config/settings.json.

Context Window Management

Local AI models operate with limited context windows. PR-AI Assistant implements automatic protection mechanisms:

  • File validation: Loaded files are rigorously validated. Executable binaries (.exe, .dll) are rejected, and character limits are applied (50,000 for text, 5,000 for hexadecimal). Excess content is automatically truncated.
  • Automatic history trimming: Before each query, the system estimates token usage. If the system prompt, forensic context, and chat history exceed the configured limit, the oldest messages are trimmed while always preserving base instructions.
  • Visual indicators: The right panel displays estimated tokens, available space, and a warning when context is near the limit in real time.

Web Search (SearXNG)

The commercial edition can enrich a query with current web results. It is the only feature in the program that uses the network, and it rests on three deliberate decisions:

  • The user decides, never the model. Search is enabled with the globe button next to the text field, one query at a time. The button only appears once the search engine address is entered in the side panel, WEB SEARCH section. There is no tool-calling: the model cannot decide to reach the Internet on its own.
  • It does not exist in the institutional edition. This is not a permission turned off in a config file: the networking code is simply not compiled into that binary. The globe button does not even appear.
  • Investigation Mode always blocks it. Even if the active profile allows it, entering Investigation Mode forces it off.
Forensic warning: with search enabled, the query text leaves the machine towards the search server, and pages from third-party sites are downloaded. Loaded evidence is never transmitted, but the question is. That is why it is forbidden in Investigation Mode. Every search is recorded in the audit log with the provider and the number of sources read.

Why SearXNG

SearXNG is a free metasearch engine that queries several engines and returns aggregated results. It was chosen because it requires no account, no API key and no credit card, and because the query leaves from a server the user controls. In a forensic tool that is more defensible than a corporate key against a commercial service: no third party is left holding a search log tied to a billing identity.

Running your own instance

This is the recommended approach. It requires Docker Desktop (free). Once only:

docker run -d --name searxng -p 8080:8080 ^
  -v "C:\searxng:/etc/searxng" ^
  --restart unless-stopped searxng/searxng

The container generates a settings.yml file in that folder. You must enable the JSON format, which is disabled by default:

search:
  formats:
    - html
    - json

Then run docker restart searxng. With --restart unless-stopped the container comes back up on its own after a reboot.

Most common error: if the JSON step is skipped, the instance works perfectly in a browser but rejects the application's queries with a 403 error. The message shown by the program names the exact file and key to change.

Configuring the application

  1. Open the side menu with the top-left button and scroll down to WEB SEARCH.
  2. Under SearXNG instance, enter the address: http://127.0.0.1:8080. It is also accepted without the scheme (127.0.0.1:8080).
  3. Check that the status below the field reads "Instance configured" in green.
  4. Choose the result freshness: last day, last week, last month, or no filter.
Note: the address is shown in plain text, not masked. It is not a credential, and the examiner should be able to see at a glance which server the query is going to.

What happens during a search

With the globe button on, the application requests 12 candidates from the search engine and downloads them in parallel batches until it has 6 pages read (10-second timeout each, capped at 10 attempts), converts them to plain text and builds the model query with numbered sources and an instruction to cite using [n]. The screen shows Searching… and then Reading pages….

More candidates than pages are requested on purpose: against real sites, roughly one in four downloads is refused — court portals, social networks and some news outlets block automated reading — so asking for 6 would yield 4 or 5 in practice.

Below the answer, a collapsible sources panel lists the title, a clickable URL, the date, and whether each page could be read. Verifying the sources is the examiner's responsibility.

Failures do not abort the query: if a page does not respond, it is reported and the rest continue. If none can be read, the model answers anyway, without sources and with an on-screen notice.

About history: the model receives the query enriched with the page text, but the conversation history stores the original question. Otherwise every turn would drag thousands of tokens of web pages along and the context would be exhausted in two exchanges.

Public instances

You can point to a public SearXNG instance instead of your own, with caveats: most have the JSON format disabled, they usually rate-limit automated use (429 error), and it means trusting your query to an unknown third party's server. For forensic work, always use your own instance.

Image Generation

The commercial edition can generate images from a prompt using a local engine running on the same machine. There is no cloud service and no account involved: the models live on disk and the GPU does the work.

It does not exist in the institutional edition. As with web search, this is not a disabled permission: the code is simply not compiled into that binary. And in the commercial edition, Investigation Mode always blocks it, even if the active profile enables it. A forensic tool that can fabricate images is a credibility problem, not a functionality one.

What you need

Two things, neither shipped with the distribution because of their size:

  • The engine: sd-server.exe, from stable-diffusion.cpp, in its CUDA build for NVIDIA cards or its Vulkan build for AMD and Intel. The CUDA one is unpacked into Tools\sd\bin\ and the Vulkan one into Tools\sd\bin-vulkan\, next to the application; if both are there, the application picks the one that suits the card. You can also pick it manually from the image models window.
  • A model package: and here is the difference from chat. An image model is three files, not one: the diffusion model, the text encoder and the VAE. If any of the three is missing, the engine will not start.

Image models offers three variants of Z-Image Turbo to download with one button: Q4_K (6.2 GB total), Q6_K and Q8_0. The window marks as Recommended the one that suits your card —Q4_K up to 16 GB of VRAM, Q6_K with 20 GB or more— and only offers to download what is not there yet: the three share the text encoder and VAE, so a second variant downloads a single file. You can also assemble your own package by pointing at the three files.

How to use it

  1. Open the side menu with the top-left button and scroll to IMAGES.
  2. The first time, open Image models and download the recommended one, or point to the three files if you already have them.
  3. If you have more than one downloaded, choose which to use in the IMAGES drop-down, the same way you choose the language model.
  4. Press Generate images. A separate window opens.
  5. Write the prompt, choose the size and press Generate image.

Turning off the image engine: below the buttons you can see whether the image engine is on. Turn off stops it without touching the chat, giving the card back to the language model; it turns on again by itself with the next image. Stop, further up, turns off both.

If you will not use it: on the start screen, below the model, there is the Image generation switch. When it is off, the image engine never starts and the chat's IMAGES section is disabled. It is remembered for next time.

The window is not modal: you can keep chatting with the language model while the image is being generated. Both engines share the same card because the image engine loads its weights only while working and releases them when done.

One image at a time

As in Gemini or ChatGPT: you ask for one image and wait. The generate button is disabled while one is in progress, and cancel stops that generation and nothing else. There is no queue and no pending list.

Cancelling stops the engine and starts it again, which is the only thing that truly interrupts a generation in progress. It takes about one second and leaves no partial files.

Size is a time decision, not a memory one

This is the opposite of what you would expect. With VAE tiling — which the application always enables — generating at 1024×1024 uses barely 200 MB more video memory than 512×512, but takes about three times as long. The window's indicator tells you whether the current configuration fits in free memory and, if it does not, what to change.

Every image can be reproduced

Next to each PNG the application writes a .json file with the same name containing everything needed to produce it again: prompt, negative prompt, size, steps, CFG, seed, sampler, the three model files and the exact command line the engine ran with.

About the seed: even when you choose "random seed", the number is drawn by the application and saved. The engine accepts a request for a random seed but does not report which one it used, and an image whose seed is unknown cannot be generated again.

Images go to %APPDATA%\PatagoniaRobot\PR-AIA\ImagenesGeneradas. The Open folder button takes you straight there.

What is recorded

If the active profile requires auditing, the fact of having generated an image is recorded — file, size, steps, CFG, seed and model — but never the prompt. The same criterion applies as for attachments in personal mode: auditing what the user writes would turn it into something else. The prompt is in the .json next to the image, which is where it is useful.

Auditing and Traceability

Each session generates a forensic log file (ai-session-YYYY-MM-DD.log) in the Logs/ folder with the following characteristics:

  • Append-only format: previous entries cannot be modified.
  • Each entry includes UTC timestamp and SHA-256 hash of the content.
  • Recorded events include: session start, disclaimer validation, examiner queries, model responses, context loading, errors, and exports.

This ensures record immutability under judicial scrutiny.

Forensic Considerations

  • PR-AI Assistant never directly accesses the original evidence. It only works with data already extracted and provided by the examiner.
  • The AI model operates completely locally: zero external connections, zero telemetry, zero data transmission.
  • Every model response automatically includes a disclaimer indicating its artificial origin and the need for examiner verification.
  • The forensic log file constitutes a complete, non-editable, and verifiable record of every interaction with the model.
